# Probability contract root-cause audit

`scripts/run_benchmark_v2.py:probs_from_pred` was the sole benchmark fallback for hard-label baselines. Before the fix it computed `one_hot * 0.998 + 0.001 / 3`, producing `[0.9983333333333333, 0.0003333333333333, 0.0003333333333333]` and a row sum of `0.999`, before CSV serialization. No rounding, JSON conversion, CSV conversion, or float32 conversion caused the defect; the invalid value was present in memory and then persisted faithfully as float64 CSV text.

Affected benchmark paths: majority baseline, G1/G2 threshold rules, and the Ridge regression classification fallback. Learned logistic, ordinal, HGB, MLP, and CNN-family paths supply native probability matrices.

The replacement is deterministic one-hot output `[1, 0, 0]`, `[0, 1, 0]`, or `[0, 0, 1]`, implemented centrally as `hard_label_probabilities`. It is the appropriate semantic representation because these rules have no calibrated confidence model. The new central validator enforces Low/Medium/High order, finite values in `[0, 1]`, sum-to-one within `1e-6`, and predicted-label/argmax agreement before the runner writes a completed prediction artifact. `1e-6` is the documented strict numerical tolerance for neural softmax values produced in float32 and serialized as float64; it is still three orders of magnitude tighter than the rejected `0.001` defect. It is not a relaxation that could admit the invalid run. The fix does not alter predicted labels or label-only metrics (accuracy, F1, QWK, ordinal MAE, confusion matrix); it can alter Brier, ECE, PR-AUC and all probability-artifact checksums. It changes no split, feature, target, tuning, seed, or selection protocol.
